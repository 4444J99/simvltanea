Use this in a GitHub.com Copilot cloud-agent research session. It requests research, not implementation or publication.

## Objective
Establish the current, source-grounded lineage and reusable audiovisual grammar of the existing Triptych / Visual Form Canon work in relation to the persona public-life project. Extend existing research; do not restart it or create a new umbrella repository.

## Read first
- Applicable repository guidance, including AGENTS.md and any Copilot instructions.
- incubator/triptych-video-canon/VISUAL_FORM_CANON.md
- incubator/triptych-video-canon/UNIFICATION.md
- The existing README, incubation notes, source files, tests and handoff documents within that directory.

## Evidence method
Record the current repository HEAD and the exact paths inspected. Distinguish repository commit SHAs from file blob SHAs.

Investigate source code, fixtures, configuration, manifests, relevant history and existing issues/PRs where accessible—not only README descriptions. Separate:
1. a historical creator statement;
2. a design proposal;
3. implemented source;
4. an executed test;
5. a verified output or deployment.

An old report saying a test passed or a file was missing is historical evidence until rechecked. Do not use generated descriptions as proof of implementation.

Trace Triptych/Tryptich, the three-panel selector, and any references to The First Circle, Floating Points, or Up the Hill Backwards to exact files when possible. An unresolved mapping is a finding; do not invent a repository, filename or relation to close it.

For each relevant artifact, report:
- stable local record ID, title, path and tags;
- dated source or commit provenance where available;
- original work / variant / derivative / reusable component relationships;
- source set and asset availability;
- visual grammar, timing, seed/randomness, interaction, audio coupling and capture behavior;
- runtime target and implementation owner;
- verification level and the smallest remaining uncertainty.

## Remote-only and privacy boundaries
Work only with authorized, remotely accessible material. Local /Users/... paths are references, not files available in the cloud session. Record missing assets and access gaps; do not silently substitute generated material for original work.

Do not assume access to other private repositories. Use the accompanying registry as supplied context, not independent proof. Cross-repository facts require explicit authorized access or must remain attributed/unverified.

Do not import personal histories, partner/client content, private prompts or raw media into public tracked files. The Portvs repository is public. Keep any sensitive findings out of public diffs.

## No mutations in this research pass
Do not change application code, default branches, publishing settings or access controls.
Do not touch Limen, config/_limen or graph.jsonl.
Do not edit adjacent implementation repositories or promote an incubating component without an explicit ownership decision.
Do not create issues, pull requests, deployments or posts for this assignment.

## Deliverable
Return one compact evidence report in the session:
- what is present and directly verified;
- a work-to-file lineage map;
- reusable components and their owners;
- missing sources and runtime verification gaps;
- contradictions or stale assumptions;
- the single highest-value next bounded task.

Do not manufacture a build failure or success. If runtime checking was not performed, say so.

## Completion rule
Stop when the directory-level lineage and evidence map is established. Do not expand into an unrestricted scan of every personal or institutional repository.
